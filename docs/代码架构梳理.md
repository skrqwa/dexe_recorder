# dexe_recorder 代码架构

> 适用于：完全没看过代码的开发者，5 分钟理解全貌

---

## 1. 入口

`src/dexe_recorder_node.cpp`（5 行）：

```cpp
int main(int argc, char** argv) {
  rclcpp::init(argc, argv);
  auto node = std::make_shared<dexe_recorder::RecorderNode>();
  rclcpp::spin(node);
  rclcpp::shutdown();
}
```

所有逻辑在 `RecorderNode` 里。

## 2. RecorderNode 构造函数

启动时做 3 件事：加载配置、创建订阅、创建服务。

### 2.1 配置加载

优先级：参数指定 > `~/workspace/dexe_recorder/config/auto_recorder.yaml` > 包 share 目录

`config/auto_recorder.yaml`：

```yaml
state_topic: "/feedback/robot_server_state"       # ~100Hz 关节状态 JSON
head_compressed_topic: "/camera/kfc_compressed"   # ~27Hz 头部相机 JPEG
hand_left_topic: "/camera_l/color/image_rect_raw" # ~30Hz 手部左相机
hand_right_topic: "/camera_r/color/image_rect_raw"# ~30Hz 手部右相机
ee_left_topic: "/feedback/ee/left"                # ~20Hz EE 反馈左
ee_right_topic: "/feedback/ee/right"              # ~20Hz EE 反馈右
output_dir: "data"
save_format: "video"
```

### 2.2 ROS2 订阅（8 个）

| 话题                               | 消息类型        | 频率     | 回调                       | 用途                       |
| ---------------------------------- | --------------- | -------- | -------------------------- | -------------------------- |
| `/feedback/robot_server_state`   | String          | ~100Hz   | `OnState`                | 关节命令+反馈              |
| `/camera/kfc_compressed`         | CompressedImage | ~27Hz    | `OnCompressedImage`      | 头部相机                   |
| `/camera_l/color/image_rect_raw` | Image           | ~30Hz    | `OnImage("hand_left")`   | 手部左相机                 |
| `/camera_r/color/image_rect_raw` | Image           | ~30Hz    | `OnImage("hand_right")`  | 手部右相机                 |
| `/feedback/ee/left`              | EEFeedback      | ~20Hz    | `OnEndEffector("left")`  | EE 反馈 -> feedback_record |
| `/feedback/ee/right`             | EEFeedback      | ~20Hz    | `OnEndEffector("right")` | EE 反馈 -> feedback_record |
| `/control/ee/left`               | EEJointControl  | 事件驱动 | `OnEeCommand("left")`    | EE 命令 -> pose_record     |
| `/control/ee/right`              | EEJointControl  | 事件驱动 | `OnEeCommand("right")`   | EE 命令 -> pose_record     |

### 2.3 ROS2 服务（3 个）

| 服务                  | 调用方式                  | 作用     |
| --------------------- | ------------------------- | -------- |
| `~/start_recording` | `recorderctl.sh start`  | 开始录制 |
| `~/stop_recording`  | `recorderctl.sh stop`   | 停止录制 |
| `~/get_status`      | `recorderctl.sh status` | 查询状态 |

## 3. 数据流：回调 -> 内存快照

所有回调**只更新内存快照**，不碰磁盘。用 `latest_state_mtx_` 互斥锁保护。

```
OnState (~100Hz)
  │ 解析 JSON -> Frame{joint_names, joint_position, joint_position_cmd, ...}
  │ 加锁 -> latest_state_frame_ = frame -> 解锁

OnEndEffector (~20Hz)
  │ 加锁
  ├── ee_left/right_name_ = msg->ee_name
  └ latest_ee_values_["LEFT_T_MCP"] = joint_states[i].position  (经 MapEeJointName 映射)
     解锁

OnEeCommand (事件驱动)
  │ 加锁
  └ latest_ee_cmd_values_["LEFT_THUMB1"] = values[i]
     解锁

OnCompressedImage (~27Hz)        OnImage (~30Hz)
  │ 直接推 GstRecorder             │ 直接推 GstRecorder
  └ 写 metadata.jsonl             └ 写 metadata.jsonl
```

## 4. 30Hz 写线程（两个独立线程）

### 4.1 WriterLoop（写 pose_record，录命令）

```cpp
每 33ms:
  加锁 -> frame = latest_state_frame_（拷贝）-> 解锁
  从 frame 取 joint_position_cmd（命令值）
  加锁 -> 合并 latest_ee_cmd_values_ -> 解锁
  组装 JSON -> 写 pose_file_ + flush
  pose_frames_.push_back（缓存，stop 时合并用）
```

### 4.2 FeedbackWriterLoop（写 feedback_record，录反馈）

```cpp
每 33ms:
  加锁 ->
    joint_map = latest_state_frame_.joint_position（反馈值）
    ee_map = latest_ee_values_（EE 反馈位置）
  -> 解锁
  组装 JSON -> 写 feedback_file_ + flush
  feedback_frames_.push_back
```

### 4.3 频率转换机制

| 源频率            | 写线程频率 | 机制                                                                     |
| ----------------- | ---------- | ------------------------------------------------------------------------ |
| robot_state 100Hz | 30Hz       | 抽帧：写线程每 33ms 取最新一份，中间的 ~3 条丢弃                         |
| EE 反馈 20Hz      | 30Hz       | 插帧：EE 50ms 来一条，写线程 33ms 取一次，约一半帧重复上一份（零阶保持） |

## 5. StartRecording / StopRecording 生命周期

```
StartRecording()
  ├── 生成 session_id（时间戳，如 20260716_102503）
  ├── 创建目录 data/20260716_102503/{head,hand}/{left,right}/
  ├── 打开 pose_record_*.jsonl.tmp
  ├── 打开 feedback_record_*.jsonl.tmp
  ├── 打开 metadata.jsonl
  ├── GstRecorder.Start()（3 条 GStreamer pipeline）
  ├── 清空内存快照（latest_ee_values_、latest_ee_cmd_values_、ee_name_）
  ├── recording_ = true
  ├── 启动 writer_thread_（WriterLoop）
  └── 启动 feedback_writer_thread_（FeedbackWriterLoop）

StopRecording()
  ├── recording_ = false          -> WriterLoop 退出
  ├── feedback_recording_ = false -> FeedbackWriterLoop 退出
  ├── join 两个线程
  ├── GstRecorder.Stop()（发 EOS flush pipeline）
  ├── 关闭文件
  ├── FinalizePoseRecord()        （jsonl.tmp -> pose_record.json）
  └── FinalizeFeedbackRecord()   （jsonl.tmp -> feedback_record.json）
```

## 6. MapEeJointName（EE 关节名映射）

与遥操 `ee_hand_mapping.py` 规则一致：

```
输入：side="left", ee_name="Linker_L6", joint_name="T_MCP"

if ee_name == "BrainCo_Revo1_R/E":
    T_MCP       -> "LEFT_HAND_THUMB1"     （强脑特殊映射，6个关节）
    T_CMC_YAW   -> "LEFT_HAND_THUMB2"
    IF_MCP_PITCH-> "LEFT_HAND_INDEX"
    MF_MCP_PITCH->"LEFT_HAND_MIDDLE"
    RF_MCP_PITCH->"LEFT_HAND_RING"
    LF_MCP_PITCH->"LEFT_HAND_PINKY"
elif ee_name in 夹爪(DH_PGC/DH_AG/Piper):
    FINGER1     -> "LEFT_GRIPPER"         （夹爪统一）
else:                                      （Linker_L6/L20, PaXini, DexHand）
    "LEFT_T_MCP"                          （直接加前缀）
```

参考：[【遥操】已适配的末端说明.md](【遥操】已适配的末端说明.md)

## 7. GstRecorder（相机录制）

独立模块，负责相机数据的硬件加速编解码。

### 7.1 三条 GStreamer pipeline

```
Head pipeline（头部 kfc_compressed 3840x1080 JPEG）:
  appsrc -> jpegparse -> nvjpegdec(硬解) -> nvvidconv(NVMM->sysmem) -> tee
    ├-> videocrop(左 0-1920) -> nvvidconv(sysmem->NVMM) -> nvv4l2h264enc -> qtmux -> filesink(head/left/video.mp4)
    └-> videocrop(右 1920-3840) -> nvvidconv -> nvv4l2h264enc -> qtmux -> filesink(head/right/video.mp4)

Hand left pipeline（手部 raw Image 640x360）:
  appsrc -> nvvidconv -> nvv4l2h264enc -> qtmux -> filesink(hand/left/video.mp4)

Hand right pipeline:
  同上
```

### 7.2 关键方法

| 方法                                     | 调用方                | 作用                             |
| ---------------------------------------- | --------------------- | -------------------------------- |
| `Start(session_dir, format)`           | `StartRecording()`  | 创建 3 条 pipeline，设为 PLAYING |
| `PushCompressedFrame(data, size)`      | `OnCompressedImage` | 推一帧头部 JPEG                  |
| `PushHandFrame(name, data, w, h, enc)` | `OnImage`           | 推一帧手部 raw Image             |
| `Stop()`                               | `StopRecording()`   | 发 EOS，等 flush，销毁 pipeline  |

### 7.3 为什么不用 OpenCV

OpenCV（opencv4tegra）的 `.init_array` 初始化与 `nvjpegdec` 的 NVMM 硬件资源初始化冲突，触发 SIGBUS。详见 [GStreamer-OpenCV冲突踩坑记录](GStreamer-OpenCV冲突踩坑记录.md)。

## 9. 线程模型

```
线程1: ROS 回调（所有话题回调）
线程2: WriterLoop（30Hz 写 pose_record）
线程3: FeedbackWriterLoop（30Hz 写 feedback_record）
线程4-6: GStreamer 内部（3 条 pipeline 各自的编解码线程）
```

### 共享变量

| 变量                                   | 保护锁                | 写方                       | 读方                           |
| -------------------------------------- | --------------------- | -------------------------- | ------------------------------ |
| `latest_state_frame_`                | `latest_state_mtx_` | OnState                    | WriterLoop, FeedbackWriterLoop |
| `latest_ee_values_`                  | `latest_state_mtx_` | OnEndEffector              | FeedbackWriterLoop             |
| `latest_ee_cmd_values_`              | `latest_state_mtx_` | OnEeCommand                | WriterLoop                     |
| `ee_left_name_` / `ee_right_name_` | `latest_state_mtx_` | OnEndEffector              | MapEeJointName                 |
| `pose_frames_`                       | `image_mtx_`        | WriterLoop                 | FinalizePoseRecord             |
| `feedback_frames_`                   | `image_mtx_`        | FeedbackWriterLoop         | FinalizeFeedbackRecord         |
| `metadata_file_`                     | `image_mtx_`        | OnCompressedImage, OnImage | -                              |

## 10. 关键设计决策

1. **回调不碰磁盘**：所有回调只更新内存快照，写盘由 30Hz 线程独立完成
2. **100Hz -> 30Hz 抽帧**：写线程每 33ms 取最新快照，中间消息自然丢弃
3. **20Hz -> 30Hz 插帧**：EE 零阶保持（重复上一帧），不做插值
4. **命令/反馈分离**：pose_record 录命令（训练 action），feedback_record 录反馈（训练 state）
5. **不依赖 OpenCV**：所有图像处理在 GStreamer pipeline 内完成
6. **流式写盘**：每帧写完立即 flush，崩溃只丢最后一帧
7. **EE 关节名映射**：与遥操 ee_hand_mapping.py 规则一致，支持多种末端设备
